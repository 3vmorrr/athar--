# Mobile watch-page research and Athar adaptation
Research date: 2026-10-25. Android is the primary product. Legacy public-web redesign is outside this increment.

## Sources and observed scope
- [YouTube Android comment help](https://support.google.com/youtube/answer/6000964?co=GENIE.Platform%3DAndroid): first-party comment/reply actions and moderation states.
- [YouTube comment settings](https://support.google.com/youtube/answer/9482556?co=GENIE.Platform%3DAndroid): ordering is a deliberate view, not invented relevance.
- [Current mobile rollout visual reference, 9to5Google, 2025-10-23](https://9to5google.com/2025/10/23/youtube-video-player-icon-redesign-rollout/): portrait and landscape screenshots, less obstructive controls, grouped actions, threaded comments. This is a dated visual reference, not proof that every2026 account has an identical layout.
- [2026 fullscreen regression report](https://www.androidauthority.com/youtube-full-screen-bug-missing-video-details-fixed-3702228/): reinforces testing restoration of metadata/comments after fullscreen. This secondary visual/product observation is not used as an API specification.
- [Official IFrame API](https://developers.google.com/youtube/iframe_api_reference), [required minimum functionality](https://developers.google.com/youtube/terms/required-minimum-functionality), [Android WebKit](https://developer.android.com/jetpack/androidx/releases/webkit).

## Original Athar design
Video first; title and scholar/series directly beneath; horizontally scrolling concise actions; collapsed description; compact first-party comment preview; collapsed current/next-series preview with a separate paginated playlist. Athar colors, Noto Sans Arabic, Material Symbols and motion tokens remain authoritative. No YouTube icons, proprietary animation/code, comments or branding are copied.

Compare two comments surfaces during emulator acceptance: bounded-height sheet that leaves the player visible, and expanded full-height sheet with one lazy comments list and an IME-aware composer. Neither duplicates the player. Never place Athar UI over a live YouTube player. Use a fullscreen comments surface where an overlapping sheet would obscure the embedded player; pause/reveal the player through explicit transitions instead. Record actual test outcomes before choosing final behavior.

Observed adaptation: the API36 portrait check could browse an in-flow panel beneath the player; the360x640dp API34 check could not display the comment because header/composer consumed the remaining height. The implementation therefore chooses full comments when the remaining body is below360dp scaled by font size; otherwise it offers in-flow comments with an explicit expand action. Reducing window height while inline comments are open promotes the full panel. Expanded comments pause/hide the provider view and closing returns to metadata on compact screens. This threshold is an Athar layout decision based on the observed failure, not a copied YouTube specification. Rerun both sizes/languages before final acceptance.

## Provider constraints
Use the official YouTube IFrame player inside a narrowly scoped OS WebView, not extracted media or a website wrapper. Native Compose owns every surrounding surface. Preserve all provider controls, ads and branding; no overlays or script modifications to provider documents. Local player HTML uses loadDataWithBaseURL with HTTPS installed application ID identity, an explicit origin and a scoped main-frame WebMessage listener. No application credentials enter HTML/JavaScript. Disable file/content access and mixed content; block arbitrary main-frame navigation. Unsupported WebMessage providers and embedded-video errors get an official YouTube handoff.

Viewport minimum is200x200 CSS pixels. Prefer16:9 at normal phone widths; use min-height200dp on narrow screens, explaining the ratio exception rather than violating provider requirements. No automatic lesson autoplay. Rotation resumes from observed position; do not promise uninterrupted audio across a destroyed activity. No YouTube background playback while another application/lockscreen is active.

Interop finding: a measured native view can still have a zero-height CSS layout viewport when its Android layout parameters use WRAP_CONTENT. [Chromium AwLayoutSizer](https://chromium.googlesource.com/chromium/src/+/HEAD/android_webview/java/src/org/chromium/android_webview/AwLayoutSizer.java) explicitly sets force-zero layout height from that flag. The Athar live probe observed native720x405px, JavaScript viewport360x203, but body/iframe height0; CSS-only/numeric-IFrame sizing did not correct it. Set native WebView layout parameters to MATCH_PARENT inside Compose's bounded player area and keep official numeric setSize/resize handling. [Android WebView guidance](https://developer.android.com/develop/ui/views/layout/webapps/webview) also uses match-parent dimensions. Verify both native layout parameters and actual CSS rectangle before claiming functional playback.

## Progress and discussion
Opening a lesson never completes it. The implemented policy uses explicit completion only. Ended events suggest the next lesson but do not grant completion; observed-coverage-based automatic completion is deferred until it can reject scrubbing-only progress. Persist throttled checkpoints and stable completion IDs; restore position by cueing, never surprise autoplay. Draft/retry states stay scoped to the lesson/account. First-party discussion supports one root plus one reply level, pagination, stable mutation IDs, status labels and an independently authorized moderation API. Replies under hidden parents are not publicly exposed.

## Acceptance gates
Build/unit/API tests; Arabic-first/light fresh-install test on an English OS; English/LTR persistence; phone/tablet/landscape; both comments-panel heights; IME and large text; offline/unavailable-video fallback; rotation/player identity; no false completion; reply visibility/idempotency/moderator authorization. Debug functional checks do not certify release jank. Release profiling remains a separate gate.
