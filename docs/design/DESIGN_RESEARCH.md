## Immersive refinement research —26 October2026

User references inform original composition and media hierarchy only. [The six-reference interpretation](IMMERSIVE_SECTION_HERO.md) records adoption/exclusions. Actual palette/type/source routes were checked in Theme.kt/MainShell.kt; accepted motion/recovery/provider/ownership contracts remain authoritative. The local UI/UX stack search was narrowed to verified Compose animation/accessibility guidance; use UI-owned native motion/semantics, without adopting the search result's newer dependency version.

Official [app-bar guidance](https://developer.android.com/develop/ui/compose/components/app-bars) supports a native scrolling/compact-header relationship. [Material3 bottom sheets](https://developer.android.com/develop/ui/compose/components/bottom-sheets) provide lifecycle/state foundations when a real draggable modal is appropriate. Athar chooses static rounded layers where dragging has no useful action, and explicit accessible alternatives for real sheets.

[Compose best practices](https://developer.android.com/develop/ui/compose/performance/bestpractices), [phase-aware reads](https://developer.android.com/develop/ui/compose/performance/phases) and [release performance guidance](https://developer.android.com/develop/ui/compose/performance) inform lazy/state/draw boundaries and actual profiling requirements. [Accessibility defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults) support native48dp interaction targets. These are implementation guidance, not measurements or proof of acceptance on Athar's phone.

[YouTube minimum functionality](https://developers.google.com/youtube/terms/required-minimum-functionality), checked26 October, reinforces keeping the provider viewport/identity and no overlapping custom hero controls. Existing [watch research](YOUTUBE_WATCH_RESEARCH.md) remains the detailed source; the new references do not override provider requirements or first-party moderation.
Primary references: [Android architecture](https://developer.android.com/topic/architecture/recommendations), [Compose accessibility](https://developer.android.com/develop/ui/compose/accessibility), [Compose performance](https://developer.android.com/develop/ui/compose/performance/bestpractices), [Media3 background sessions](https://developer.android.com/media/media3/session/background-playback). Adopt predictable destinations, expressive but restrained Material surfaces, semantic controls, lifecycle-aware state and reduced motion.

[Qanet's public site](https://www.qanet.app/ar) describes nightly logging, milestones, calculator, consistency/calendar insights and an offline companion; store descriptions must be checked separately before attributing further details. Athar implements the approved addendum independently. Reject its lowest-tier character judgment and fixed reading-time promises. Milestones describe recorded counts rather than spiritual acceptance. No Qanet assets/code/layouts are copied.

Existing Athar green/ivory/copper palette and Arabic typography govern both applications. The local UI/UX skill returned an unrelated teal/Latin-font palette, which was rejected. Its accessibility/touch/spacing guidance remains useful. Use compact bottom navigation and expanded rail; detail screens hold advanced features. Administrative tables get desktop density and mobile labeled rows. Large blank decorative panels, all-in-one settings pages and controls smaller than 48 dp are rejected.
