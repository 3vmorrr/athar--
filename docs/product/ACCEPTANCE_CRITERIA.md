# Release acceptance gates
Each implemented feature must pass its feature specification and have a dated evidence entry. Required cross-cutting gates: verified mandatory Android auth; revocable sessions; ownership and privilege isolation; Arabic/English RTL/LTR; no content placeholder presented as functional; no invented religious text; complete errors/offline states; no regressions in existing web functionality; additive data migration; private-data export/deletion; original approved branding; reproducible debug build; release signing instructions without keys; realistic host compatibility.

Quran must have all 114 surahs and 6236 indexed verses with correct page/juz/hizb references. Night Prayer must pass boundary, DST, historical-edit, streak, duplicate-sync and local-privacy cases. Audio/background behavior requires a real device/emulator test. SMTP requires actual provider message acceptance and recipient confirmation before claiming delivery. A dependency-blocked feature remains blocked with an honest unavailable state. See [Definition of done](../engineering/DEFINITION_OF_DONE.md).
