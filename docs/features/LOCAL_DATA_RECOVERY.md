# Unreadable local records and safe recovery

Status: TESTED scoped increment within IN_PROGRESS phase2. Protected observer states, strict counter/reading validation, retained Night Prayer/exemption reads and localized recovery UI have functional code and executed device evidence. This addresses the core-observer part of QF03 without resetting the application or its encryption key; it does not complete every offline/synchronization requirement.

An unreadable encrypted record is different from an absent record. A failed authentication tag, malformed payload, unavailable key or database read must not become a zero counter, empty prayer history or missing reading marker presented as valid data. Preserve ciphertext, ownership, pending operations and revisions. Do not silently delete, replace with defaults, mark work complete or retry an unverified mutation.

Use an explicit loading/ready/unreadable read state at observer/UI boundaries. Strict mutation decoders continue to fail closed. Catch ordinary read failures without swallowing coroutine cancellation; do not expose exception messages, plaintext notes, identifiers or key material in user feedback/logs. Give a localized explanation and a read-only retry that resubscribes to the retained source. Successfully readable Quran/source content can remain usable while affected private editing and analytics are disabled. Unreadable personal data must not be treated as an empty statistics dataset.

Scope includes Quran position, adhkar counter, Night Prayer history/calendar and private exemptions. Shared cached-content/watch/account error surfaces must also be reviewed; do not claim full recovery from a narrow observer fix. A permanently lost Android Keystore key cannot be reconstructed by a retry. Restoration requires an appropriate genuine backup/key or an explicit separately designed recovery choice; never promise automatic recovery or wipe retained data to hide the error.

`core/data/ProtectedRead.kt` distinguishes Loading/Ready/Unreadable, propagates cancellation and carries no exception text. UI retries explicitly resubscribe. Counter/reading writes still use strict domain-validated decoders; malformed/defaulted Gson objects are not accepted as zero progress. Night Prayer editing validates an existing payload before replacing it, and an unreadable history is not rendered as zero totals. Private exemption writes validate the retained record before replacement; owner is captured and rechecked. Calendar/form read state is keyed to the owning ViewModel/account. Reader error feedback scrolls with source content rather than consuming the entire large-font viewport.

Night Prayer date, verse count and measured-duration columns must agree with the decrypted payload before appearing in private history/pace calculations. Invalid metadata cannot silently fabricate totals from an otherwise valid encrypted record. Inclusive verse counting uses the same local helper for writing and reading, with checked arithmetic.

The fixture UI case restores snapshots in `finally` and removes only its own fresh UUID row; it does not clear an account or the real application partition. Cryptographic tests include malformed Base64, altered authentication tags and invalid decoded objects. Genuine key invalidation on the user's installed app is deliberately not performed.
