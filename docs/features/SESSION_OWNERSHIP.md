# Native authentication request boundaries

Status: task02.4 functional and applicable verification gates PASS26 October2026. This extends the existing session-generation/actor guards; it does not replace backend session rotation, authorization or encrypted credential storage.

Source review and deterministic coroutine tests reproduced two defects: a former actor's completed response could survive a direct new sign-in, and a former refresh could replace/sign out the newly signed-in account. Prior generation invalidation covered explicit logout but not a new authentication attempt. Baseline `session-race-before-fix.log`:8 targeted cases,2 fail. The failed baseline is retained; it is not a stable-build result.

New authentication intent invalidates older requests before dispatch. Successful login/registration establishes a second boundary while saving/publishing the new session, so requests started against the former account during the sign-in wait cannot complete afterward. A failed sign-in leaves existing stored credentials intact; an old response must never clear a newer account. Refreshes for the same active session remain coalesced and do not create this new-authentication boundary. Logout continues to invalidate requests and remove credentials explicitly.

Authentication intent and credential persistence share the session mutex. A new attempt waits for an already-running atomic credential save rather than incrementing generation in the middle of that save and accidentally invalidating the newer intent. Network calls are outside this lock. No raw token/password/provider message is logged or included in an error state.
