# Route and API audit
Static route evidence is indexed in [SOURCE_OUTLINE](SOURCE_OUTLINE.md). Baseline public HTML: `/`, `/quran`, `/hadith`, `/dorar`, `/books`, `/lessons`, `/scholar`, `/series`, `/adhkar`, `/about`. Auth: `/register`, `/login`, `/logout`, `/forgot-password`, `/reset-password`, `/verify-email` redirect. Account/admin are server-rendered cookie routes with many action kinds in one front controller.

Existing unversioned APIs: POST `/api/quran/progress`, `/api/favorites`, `/api/adhkar/completion`, `/api/lesson/progress`; GET `/api/hadith/search`, `/api/dorar/search`. Provider proxies use server tokens; most Quran/audio/catalog/adhkar calls occur directly from browser JavaScript. These are not a complete mobile API and may return HTML redirects from cookie auth. Content mutations, comments, downloads, image reads and owner recovery have separate non-API routes.

Private writes require actor/CSRF; catalog visibility is SQL-filtered. Browser-only integrations include WebAudio/AudioWorklet, JS ONNX SDK, DOM translation, localStorage, IFrame video, MediaSession and browser caching. Native replacements require repositories/platform implementations rather than copying DOM/worker logic. New `/api/v1` routes need pure JSON/auth ownership, schema/rate validation, consistent errors and bounded pagination. Refer to each feature spec for missing tests/Android/admin outcome.
