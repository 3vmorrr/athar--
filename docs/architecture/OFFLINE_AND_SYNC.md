# Offline data and synchronization
After successful initial verified authentication and local initialization, Room serves cached permitted content and personal state. Public provider content retains provenance, license/version and cache timestamps; expired metadata may be shown with a stale indicator where lawful. No fabricated Quran text or prayer time is used on cache miss.

Account-owned local data is partitioned by user ID and cleared or locked on logout/account switch. Mutations enter an outbox in the same transaction as the local edit. Stable UUIDs and request keys make retries idempotent. Compare-and-swap server versions reject conflicting historical edits with 409 and return the current revision; do not silently overwrite. Tombstones prevent deleted rows from resurrection; deletion clears note/range content. Offline auth never bypasses an explicit logout/revocation once observed. Exempt periods stay out of ordinary sync and exports unless separately disclosed/authorized.

Current implementation: [persistent progress work](../features/PERSISTENT_SYNC.md) is account/environment scoped with bounded retries and six-hour eventual maintenance. Worker HTTP, durable scheduling and real OS network-restoration/reboot are separate gates. [Disposable response-cache limits](../features/CONTENT_CACHE.md) are being verified separately; never classify private progress/outbox as an evictable HTTP response. Cached live/upcoming status is explicitly saved/offline context, not fresh authority to start live playback. Data remains locked by owner after ordinary logout rather than being silently erased.
